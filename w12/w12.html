Core. Simulate 10,000 nights with a limit of 150 (set.seed(12) first). Find the average, its standard error, the 90% range and the share of nights with a walk.

TipHint

copy R 12.3 and change 170 to 150.

NoteAnswer (try first)

Core. Average €9,376.78 (exact €9,377.19), SE €6.41; 90% of nights between €8,337.03 and €10,394.22; a walk on 1.1% of nights. Compared with your 170 run (R 12.3): €618.27 less a night on average in these simulations (the exact difference is €622.18), but walks are rare.

set.seed(12)
limit <- 150
revenue <- numeric(10000)
walked <- numeric(10000)
for (i in 1:10000) {
  arrive <- rbinom(1, limit, show)
  walked[i] <- max(arrive - rooms, 0)
  revenue[i] <- min(arrive, rooms) * rate - walked[i] * walk_cost
}
mean(revenue)
sd(revenue) / sqrt(10000)
quantile(revenue, c(0.05, 0.95))
mean(walked > 0)

Challenge. The rule: accept bookings while \(P(\text{walk}) \le \text{rate}/(\text{rate} + 250)\). Find the largest limit that meets it with 1 - pbinom(100, L, show) for L <- 100:200, and compare with the simulated best.

No starting code here: write it from the question. The hint above points the way, and the full answer is at the end of this handout.

TipHint

1 - pbinom(100, L, show) is the chance of a walk for each limit in L; keep the limits where it is at most the ratio, then take the largest with max().

NoteAnswer (try first)

Challenge. The ratio is 0.302; the largest limit that meets it is 168. The exact best average is at 167: the rule lands next to it. To be exact, the last booking causes a walk only if it turns up and at least 100 of the others do, 1 - pbinom(99, L - 1, show); with that version the rule gives 167, the best exactly.

ratio <- rate / (rate + 250)
L <- 100:200
p_walk <- 1 - pbinom(100, L, show)
max(L[p_walk <= ratio])
# exact version: the last booking walks only if it turns up and at least 100 of the others do
max(L[1 - pbinom(99, L - 1, show) <= ratio])

R 12.7 · Going further (optional)

For when you have time, in class or later. Not needed for the Mission Set or the quiz.

Which show-up chance? The Week 2 puzzle returns. Almost all non-refundable bookings cancel (Week 2: mostly group and agent blocks), and they are about one city booking in six. If the bookings you overbook are ordinary ones, the chance that each turns up is higher than the 58% used all week.

NoteYou should see

Without the non-refundable bookings, about 69% turn up, not 58%. With that chance a limit of 167 walks a guest on almost every night, and the best limit is about 140. The method is the same; the input changed the answer. Before you trust a simulation, ask how its inputs were recorded.

NoteType this to your AI assistant

“A hotel accepts 170 bookings for 100 rooms. Each booking turns up with probability 0.578, independently. What is the probability that more than 100 turn up?”

“I ran my simulation twice and got different averages. Is my code wrong?”

Check the first answer: 1 - pbinom(100, 170, 0.578) = 0.365. Many assistants use a normal approximation; it should land close. Check the second: no. Without set.seed(), each run uses new random numbers; the averages should differ by about a standard error. AI says, R checks.

Commands to know

These can be assessed in the quiz: set.seed(), rbinom(n, size, prob), numeric() with a for loop that stores each run, quantile(x, c(0.05, 0.95)), mean(x > a) for a simulated probability, and a simple for loop. Remember: a simulated average is an estimate with a standard error, and a recommendation needs its risk and its assumptions.
